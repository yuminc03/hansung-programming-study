# 폴더 자동 정리

폴더 경로를 받아 **탐색 → 계획 → 복사 정리 → 개수 검산 + 정리로그** 순서로 정리한다.

이 순서를 지키는 이유는 두 가지다. 분류와 이름 짓기는 판단이 필요하므로 실행 전에 계획을 사람에게 보여 주고,
실행 뒤에는 "파일을 잃어버리지 않았는가"를 사람의 눈이 아니라 스크립트로 검산한다.
그리고 원본은 절대 건드리지 않고 **복사만** 한다. 무엇을 지울지는 정리된 결과를 본 사람이 결정한다.

## 입력

`$ARGUMENTS` = `<원본 폴더 경로> [결과 폴더 경로] [--yes]`

- 원본 폴더 경로는 필수다. 없으면 어느 폴더를 정리할지 묻는다. 공백이 있으면 따옴표로 감싼다.
- 결과 폴더의 기본값은 `<원본의 부모>/<원본 폴더명>_정리결과`다. 이미 있으면 뒤에 `_YYYYMMDD`를 붙인다.
  결과는 반드시 원본 폴더 **밖**에 둔다.
- `--yes`가 있으면 계획 승인 질문을 건너뛴다. 원본이 안전하므로 가능한 선택이다. 없으면 승인을 받는다.

```
<결과폴더>/
├─ 정리된폴더/   분류 폴더와 복사본
└─ 정리로그.md
```

## 도구

`${CLAUDE_SKILL_DIR}/scripts/cleanup.py` (파이썬 3, 표준 라이브러리만 사용. `python`이 없으면 `python3`나 `py`).
PowerShell에서 한글이 깨지면 먼저 `[Console]::OutputEncoding = [Text.Encoding]::UTF8`를 실행한다.
계획·스냅샷·로그 조각 같은 임시 파일은 스크래치패드(없으면 임시 폴더)에 둔다. 원본 폴더 안에는 아무것도 만들지 않는다.

| 명령 | 하는 일 |
|---|---|
| `scan <원본> --snapshot <snap.json>` | 종류별 분포, 중복·버전·이름 모호 파일, 작은 텍스트 미리보기를 출력하고 원본 스냅샷을 저장 |
| `copy <원본> <계획.tsv> <결과폴더> --snapshot <snap.json> [--dry-run]` | 사전 점검(모든 파일 배정, 충돌·확장자 변경·덮어쓰기 없음)을 통과할 때만 복사 |
| `verify <원본> <계획.tsv> <결과폴더> --snapshot <snap.json> --log [--extra extra.md]` | 개수·누락·중복 배치·내용(MD5)·원본 무변경 검산 후 정리로그 작성. 실패하면 종료 코드 1 |

스크립트에는 삭제·이동 코드가 없다. 대용량 폴더(2GB 이상)는 `--quick`(크기만 비교)을 쓸 수 있다.

## 절차

### 1. 인벤토리 (아무것도 만들지 않는다)

`scan`을 실행하고 결과를 요약해 보고한다. 파일 수, 종류별 분포, 눈에 띄는 문제(중복 의심, 버전 중복, 이름만으로 내용을 알 수 없는 파일).
내용 판단이 필요하면 작은 텍스트 파일만 열어 본다. 이미지·PDF·압축 파일은 열거나 풀지 않고 이름·날짜·크기로만 판단한다.
파일이 2000개를 넘으면 하위 폴더 단위로 나눠 정리하자고 제안한다.

### 2. 계획

아래 [규칙](#규칙)으로 **모든 파일에 한 행씩** 배정한 계획 파일을 쓴다. UTF-8 탭 구분이다.

```
원본상대경로<TAB>새폴더(/로 구분)<TAB>새이름<TAB>비고
```

`copy --dry-run`으로 사전 점검하고, 실패하면 사유(누락, 충돌, 확장자 변경 등)를 고쳐서 통과할 때까지 반복한다.

`--yes`가 없으면 사용자에게 계획을 보여 주고 **한 번만** 승인을 받는다. 다음을 포함한다.
1. 폴더별 파일 수 표
2. 이름 규칙 요약과 대표 예시 (파일이 60개 이하면 전체 배정표, 더 많으면 폴더별 요약 + 예시 + 계획 파일 경로)
3. 중복 후보, 4. 버전 세트와 최신본 판정 근거, 5. 분류 보류 목록, 6. 가정과 불확실한 점

수정 요청이 있으면 계획을 고치고 dry-run을 다시 한다. `--yes`이면 요약만 보여 주고 바로 진행한다.

### 3. 복사

`copy`를 dry-run 없이 실행한다. 스크립트는 스냅샷 이후 원본이 바뀌었으면 거부하므로, 그럴 땐 `scan`부터 다시 한다.

### 4. 검산과 정리로그

Claude가 판단한 내용은 `extra.md`로 쓴다. 제목은 아래를 쓴다.
- `## 버전 파일 처리` (세트별 최신본과 구버전, 순서 판정 근거)
- `## 분류 보류 목록` (파일별 보류 사유)
- `## 가정과 확인이 필요한 사항`
- 필요하면 `## 중복 후보 판단` (어느 쪽이 정본 후보인지)

`verify --log --extra extra.md`를 실행한다. 개수 검산, 폴더별 개수, 원본 → 새 이름 표, 내용이 같은 파일 묶음, 검증 상세는 스크립트가 자동 작성한다.
검증이 실패하면 출력이 짚은 파일(누락, 내용 다름, 계획에 없는 파일)을 이름까지 찾아 보완한다. 결과 폴더가 이미 차 있으면 `copy`가 거부하므로
누락된 파일만 계획대로 직접 복사하거나 새 결과 폴더로 다시 한다. 보완 뒤 `verify`를 다시 실행하면 기존 로그 맨 아래에 재검증이 추가된다.

### 5. 보고

원본 N개 = 정리 후 N개인지, 폴더 구조, 중복 후보(삭제하지 않았음), 구버전, 분류 보류, 가정과 확인이 필요한 사항, 로그 경로를 알린다.
원본 삭제나 이동 같은 후속 조치는 사람이 결정한다고 분명히 적는다.

## 규칙

### 분류 폴더
- 폴더의 실제 내용에서 출발한다. 템플릿을 억지로 채우지 않고, 빈 분류는 만들지 않는다.
  흔한 후보는 회의·메모, 보고서·발표, 데이터, 이미지(디자인 소재 / 사진·캡처), 문서(PDF), 메일·초안, 압축·백업이다.
- 최상위 폴더는 대략 5~10개, 깊이는 2단계 안팎으로 한다. 한 폴더에 30개를 넘게 담게 되면 종류나 연·월로 나눈다.
- 폴더 이름은 `01_회의_메모`처럼 번호 접두어로 순서를 고정하고, 가운데점(`·`)·괄호·공백은 쓰지 않는다. 키보드로 경로를 치기 불편하다.
- 내용을 알 수 없는 파일은 `99_분류보류/`에 원래 이름 그대로 둔다(빈 파일과 한 줄 메모처럼 하위로 나눠도 된다).

### 파일명
- 형식은 `날짜_내용[_세부][_버전 또는 상태].확장자`다. 날짜는 `YYYYMMDD`, 월 단위면 `YYYYMM`을 쓴다.
- 날짜는 이름이나 **내용**에 적힌 것만 쓴다. 파일 수정일은 복사·다운로드 시각일 뿐이라 쓰지 않는다.
  알 수 없으면 지어내지 않고 `미상`을 넣는다. 단가표나 로고처럼 계속 쓰는 기준 자료는 날짜를 생략한다.
- `_`로 구분하고 공백·괄호는 쓰지 않는다. **확장자는 절대 바꾸지 않는다**(스크립트가 막는다).
- "최종", "진짜최종", "복사본", "(1)" 같은 표기는 이름에서 뺀다. 버전은 `v1, v2…`, 중복은 `_중복후보`로 표현한다.
- 사용자가 따르라고 한 이름 규칙이 있으면 그것이 우선이다.

### 버전 파일
- 이름에서 v1, v2, 최종, final, draft 등을 뗀 뒤 같아지는 묶음을 버전 세트로 본다. 순서는 이름과 본문 문구
  ("팀장 피드백 반영본" 등)로 추정하고, 확실하지 않으면 가정에 적어 승인 때 확인한다.
- **최신본만 상위에** 두고 나머지는 같은 폴더의 `구버전/`에 둔다. 이름의 "최종"이 최신이라는 보장은 없으므로 내용으로 판단한다.

### 중복
- 삭제는 어떤 경우에도 계획에 넣지 않는다. 내용이 같으면 `중복 후보`로만 기록한다.
- 이름에 괄호나 "복사본"이 없는 쪽을 정본 후보로 임시 지정하고, 다른 쪽에 `_중복후보`를 붙인다. 최종 판단은 사람이 한다.
- 크기가 매우 작은 파일(스크립트는 64바이트 이하를 '작은 파일'로 표시)은 해시가 같아도 더미일 수 있다. 내용을 확인하기 전에는 중복으로 판정하지 않는다.
- 같은 회의의 메모와 정식 회의록, 시안 a/b처럼 내용이 다르거나 대안 관계인 파일은 중복이 아니다.

### 민감 정보
전화번호·비밀번호·계정 정보 등이 있는 파일은 분류 보류로 두고, 계획과 로그에는 값을 옮겨 적지 않고 "전화번호 형식 문자열"처럼 종류만 적는다.

## 이 스킬이 하지 않는 것
- 원본 삭제·이동·이름 변경, 중복 파일 삭제, 압축 파일 해제, 파일 내용 수정.
- 이동 방식의 정리. 복사 결과를 확인한 뒤 원본을 어떻게 할지는 사용자가 정한다.
