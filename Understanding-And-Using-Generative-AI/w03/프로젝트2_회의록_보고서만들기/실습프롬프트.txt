【프로젝트 2】 회의록 → 요약 → 보고서 → 공유메일 (17~19강)

기본 원칙: 탐색 → 계획 → 구현 → 검증. 모든 프롬프트는 6요소.

==================================================
STEP 0. [탐색] 회의록 파악 
==================================================

목표: 어떤 회의였고 어떤 내용이 오갔는지 파악
자료: 프로젝트2_회의록_보고서만들기의 자료/회의록.txt
주의: 아직 아무것도 만들지 마. 설명만 해줘.

==================================================
STEP 1. 회의록 요약 
==================================================

1-1. [계획] 프롬프트:

목표: 팀장 보고용 회의록 요약의 작성 계획 수립
자료: 자료/회의록.txt
형식: 핵심 요약 / 결정사항 / 담당자별 할 일 / 확인 필요 사항 — 4개 부분
주의: 계획만 세우고 아직 만들지 마.
확인: 4개 부분에 회의 내용이 빠짐없이 배정되는지.
계획이 완료되면 구현으로 넘어가줘!

1-2. [구현] 프롬프트:

목표: 방금 세운 계획대로 회의록 요약 작성
자료: 자료/회의록.txt
형식: 회의에 참석하지 않은 사람도 한눈에 이해할 수 있게.
      "이번 주 목요일"처럼 요일로만 적힌 기한은 회의록 맨 위
      날짜를 기준으로 실제 날짜로 환산.
저장: 결과물/회의록_요약.md
주의: 회의록에 없는 내용은 지어내지 말 것.
확인: 담당자와 기한이 원본 회의록과 일치하는지.
구현이 완료되면 검증으로 넘어가줘!

1-3. [검증] 프롬프트:

목표: 요약의 기한 표기 정확성 검증
자료: 결과물/회의록_요약.md ↔ 자료/회의록.txt 대조
주의: 문제가 없으면 "이상 없음"이라고만 답해도 된다.
확인: 담당자별 할 일의 기한 표기가 원본과 정확히 대응하는가.

※ "고칠 게 없다"는 답도 정상입니다 — 그 확인이 검증 단계의 목적입니다.

==================================================
STEP 2. 요약 → 업무보고서 
==================================================

2-1. [구현] 프롬프트:

목표: 팀장에게 보고할 업무보고서 초안 작성
자료: 결과물/회의록_요약.md
형식: 00_공통_템플릿/보고서_템플릿.md 구조
      (1.핵심 요약 2.진행 내용 3.결정 사항 4.이슈 사항 5.다음 액션)
저장: 결과물/업무보고서_초안.md
주의: 요약에 없는 내용을 추가하지 말 것.
확인: 5개 부분이 모두 채워졌는지.
구현이 완료되면 검증으로 넘어가줘!

2-2. [검증] 프롬프트:

목표: 보고받는 사람 기준으로 보완
자료: 결과물/업무보고서_초안.md
주의: 내용 추가 없이 순서·강조만 조정.
확인: 팀장이 이번 주에 결정해야 할 것이 맨 위에 보이는가.

==================================================
STEP 3. 보고서 → 공유메일 
==================================================

3-1. [구현] 프롬프트:

목표: 팀원들에게 공유할 사내 공유 메일 초안 작성
자료: 결과물/업무보고서_초안.md
형식: 00_공통_템플릿/메일_템플릿.md 구조.
      제목은 핵심 용건이 한눈에, 본문은 10줄 내외(30초 안에 읽히게),
      각자 해야 할 일(담당자별 액션)이 눈에 띄게.
저장: 결과물/공유메일_초안.md
주의: 공손하고 간결하게. 보고서에 없는 내용 금지.
확인: 담당자별 할 일이 전부 들어갔는지.
구현이 완료되면 검증으로 넘어가줘!

3-2. [검증] 프롬프트:

목표: 기한 임박 순으로 재배치
자료: 결과물/공유메일_초안.md
주의: 오늘 날짜 기준으로 판단.
확인: 기한이 임박한 할 일이 메일 상단에 오는가.

==================================================
마무리 확인:
결과물 폴더에 3개 파일(회의록_요약 / 업무보고서_초안 / 공유메일_초안).
회의록.txt 파일 1개가 결과물 3개가 된 것을 폴더에서 직접 확인하세요.
(→ "AI 결과물이 다음 작업의 재료가 된다"가 이 프로젝트의 핵심입니다)



(스킬적용 자동화)
지금 사용한 방법을 적용해서 회의록 파일을 불러오면 요약파일,업무보고서,공유메일 초안이 자동으로 만들어지는 스킬을 만들어줘!


(보너스) 메일 초안을 진짜 메일로 연결하기

목표: 공유메일 초안을 더블클릭하면 메일 프로그램에서 바로 열리는
      실제 메일 파일(.eml)로 변환
자료: 결과물/공유메일_초안.md
형식: 제목·받는 사람·본문이 채워진 .eml 파일 1개.
      받는 사람은 예시 주소(team@hanbitliving.example)로.
      파이썬 표준 라이브러리만 사용할 것 (별도 설치·계정 불필요).
저장: 결과물/공유메일.eml
주의: 자동 발송 기능은 절대 넣지 말 것 — 파일 생성까지만.
      발송 버튼은 사람이 누른다 (자동화의 안전선).
확인: 생성된 .eml을 더블클릭하면 메일 프로그램에서 제목과 본문이
      채워진 채 열리는가. (열어서 확인 후 받는 사람만 바꿔 발송하면 끝)
