## 1. 프로그램 개요

플레이어는 1,000P로 시작합니다. 럭키박스를 한 번 열 때마다 200P를 쓰고, 상품 4종 중 하나가 확률에 따라 무작위로 당첨됩니다. 당첨된 상품은 획득 목록에 쌓이고, 목록에서 기록을 삭제하거나 상품의 상세 정보를 볼 수 있습니다. 초기화 버튼을 누르면 처음 상태로 돌아갑니다.

## 2. 전체 프로그램 구성

### 2.1 파일 구성

| 파일            | 역할                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------- |
| `App.js`        | 게임 전체 화면을 구성하고, 모든 상태(State)와 이벤트 처리 함수를 관리하는 최상위(부모) 컴포넌트 |
| `PointBoard.js` | 닉네임 입력창, 보유 포인트, 박스 이용 횟수를 표시하는 자식 컴포넌트                             |
| `LuckyBox.js`   | 럭키박스 열기 버튼, 당첨 결과, 포인트 부족 안내, 상품 4종과 당첨 확률을 표시하는 자식 컴포넌트  |
| `PrizeList.js`  | 상품별 획득 개수, 당첨 순서 목록, 상품 상세 정보, 초기화 버튼을 표시하는 자식 컴포넌트          |
| `prizes.js`     | 게임 설정값(시작 포인트, 박스 비용, 닉네임)과 상품 데이터 4종을 모아 둔 파일                    |
| `App.css`       | 전체 화면 스타일 (직접 작성)                                                                    |
| `index.js`      | `App` 컴포넌트를 화면(root)에 그려 넣는 진입점                                                  |

### 2.2 컴포넌트 구조

```
App (상태 보관, 이벤트 처리 함수)
├── PointBoard   ← nickname, points, openCount / 닉네임 변경 함수
├── LuckyBox     ← points, cost, prizes, lastResult, message / 박스 열기 함수
└── PrizeList    ← wins, prizes, selectedPrize / 삭제, 상세 보기, 상세 닫기, 초기화 함수
```

### 2.3 데이터 흐름

- 게임의 상태(State)는 `App` 한 곳에서만 관리합니다.
- 자식 컴포넌트는 `App`이 넘겨준 값(Props)을 받아 화면에 그리기만 합니다.
- 사용자가 자식 컴포넌트에서 버튼을 누르거나 입력하면, 자식은 `App`이 Props로 넘겨준 함수를 호출합니다. 그러면 `App`의 State가 바뀌고, 바뀐 값이 다시 자식에게 전달되어 화면이 새로 그려집니다.
- 이처럼 상태를 부모에 모아 두고 자식에게 내려주는 방식을 "상태 끌어올리기(Lifting State Up)"라고 합니다. 한 컴포넌트가 바꾼 값을 다른 컴포넌트가 함께 써야 할 때 값이 어긋나지 않게 해 줍니다.

### 2.4 App의 상태(State)

| 상태            | 초기값                          | 설명                                                            |
| --------------- | ------------------------------- | --------------------------------------------------------------- |
| `nickname`      | `"추유민"` (`DEFAULT_NICKNAME`) | 닉네임 입력창의 값                                              |
| `points`        | `1000` (`START_POINTS`)         | 보유 포인트                                                     |
| `wins`          | `[]`                            | 당첨 기록 배열. `{ recordId, prize }` 객체가 당첨 순서대로 쌓임 |
| `lastResult`    | `null`                          | 마지막으로 당첨된 상품 (아직 없으면 `null`)                     |
| `openCount`     | `0`                             | 박스 이용 횟수                                                  |
| `message`       | 안내 문구                       | 박스 영역에 보여 주는 안내 및 결과 메시지                       |
| `selectedPrize` | `null`                          | 우클릭으로 고른 상세 정보 상품                                  |

`nextRecordId`는 `useRef`로 만든 번호표입니다. 값이 바뀌어도 화면을 다시 그리지 않으며, 당첨 기록마다 1부터 고유 번호를 붙이는 데 씁니다.

### 2.5 컴포넌트별 역할

**App.js**

- 위 상태들을 `useState`로 만들고, 상태를 바꾸는 함수들을 작성합니다.
- 함수: `changeNickname`, `openBox`, `deleteWin`, `showDetail`, `closeDetail`, `resetGame`
- 자식 컴포넌트 세 개를 순서대로 배치하고 필요한 Props를 넘깁니다.

**PointBoard.js**

- 표시 내용: 닉네임 입력창, "○○님의 보유 포인트" 카드(포인트 숫자는 쉼표 표시), "박스 이용 횟수" 카드
- Props: `nickname`, `onNicknameChange`, `points`, `openCount`
- 닉네임이 비었거나 공백만 있으면 기본 닉네임(추유민)을 대신 보여 줍니다.

**LuckyBox.js**

- 표시 내용: 당첨 전에는 🎁 선물 상자, 당첨 후에는 당첨 상품 이모지와 이름, 안내 메시지, "럭키박스 열기 (200P)" 버튼, 포인트 부족 경고, 상품 4종 카드
- Props: `points`, `cost`, `prizes`, `lastResult`, `message`, `onOpen`
- 보유 포인트가 200P 미만이면 버튼을 비활성화하고 경고 문구를 보여 줍니다.
- 상품 4종 카드는 당첨 확률이 낮은 순서로 정렬해서 보여 줍니다.

**PrizeList.js**

- 표시 내용: "획득한 선물 (N개)" 제목과 초기화 버튼, 상품별 획득 개수, 당첨 순서 목록, 상세 정보 카드
- Props: `wins`, `prizes`, `selectedPrize`, `onDelete`, `onShowDetail`, `onCloseDetail`, `onReset`
- 당첨 기록이 없으면 "아직 획득한 선물이 없습니다."를 보여 줍니다.
- 목록 항목에서 더블클릭하면 삭제, 우클릭하면 상세 정보를 엽니다.

**prizes.js**

- 게임 설정값과 상품 데이터를 한 곳에 모아 둡니다. 확률이나 포인트를 바꿀 때는 이 파일만 고치면 됩니다.
- 다른 파일에서는 `import { ... } from "./prizes"`로 필요한 값만 가져다 씁니다.

## 3. 주요 기능의 구현과 동작 과정

### 3.1 게임 시작과 초기 화면

게임을 열면 `App`의 State가 초기값으로 설정됩니다. 닉네임은 "추유민", 포인트는 1,000P, 박스 이용 횟수는 0회, 당첨 기록은 빈 배열입니다.

이 상태에서 화면에는 닉네임 입력창, "추유민님의 보유 포인트 1,000P", 박스 이용 횟수 0회, 🎁 선물 상자와 "어떤 선물이 나올까요?" 문구, 상품 4종 카드, "획득한 선물 (0개)"와 "아직 획득한 선물이 없습니다." 문구가 나타납니다.

### 3.2 럭키박스 열기 (`openBox`)

'럭키박스 열기' 버튼을 누르면 `App`의 `openBox`가 실행되고, 다음 순서로 처리합니다.

1. **포인트 확인**: 보유 포인트가 박스 비용(200P)보다 적으면 안내 메시지만 보여 주고 함수를 끝냅니다. 버튼이 비활성화되어 있으므로 평소에는 이 조건에 닿지 않는 방어 코드입니다.
2. **상품 뽑기**: `pickPrize()`로 확률에 따라 상품 하나를 고릅니다.
3. **기록 만들기**: `{ recordId, prize }` 형태의 당첨 기록을 만들고, `nextRecordId`를 1 올립니다.
4. **포인트 계산**: `setPoints((prev) => prev - BOX_COST + prize.reward)`로 박스 비용을 빼고 당첨 포인트를 더합니다.
5. **화면 상태 갱신**: 당첨 목록 맨 뒤에 기록을 추가하고, `lastResult`를 이번 상품으로 바꾸고, 이용 횟수를 1 올리고, 결과 메시지(예: "🎉 축하합니다! 🍫 초콜릿 당첨! (+50P 적립)")를 설정합니다.

**당첨 확률 뽑기 (`pickPrize`)**

```javascript
function pickPrize() {
  const random = Math.random() * 100; // 0 이상 100 미만의 난수
  let sum = 0; // 지금까지 더한 확률의 합
  for (let i = 0; i < PRIZES.length; i++) {
    sum += PRIZES[i].chance;
    if (random < sum) {
      return PRIZES[i];
    }
  }
  return PRIZES[PRIZES.length - 1];
}
```

확률을 앞에서부터 누적해 구간을 나누고, 난수가 속한 구간의 상품을 당첨시킵니다. 상품 배열 순서대로 초콜릿(0~40), 곰인형(40~60), 무선 이어폰(60~70), 영화관람권(70~100) 구간입니다. 예를 들어 난수가 55이면 40 이상 60 미만이므로 곰인형이 당첨됩니다. 이 방식이면 상품마다 확률을 따로 정할 수 있고, 확률 합계가 100이 아니어도 마지막 상품이 안전하게 당첨됩니다.

포인트는 `setPoints(prev => ...)` 형태로 이전 값을 기준으로 갱신합니다.

### 3.3 포인트 부족 처리

- `LuckyBox`에서 `canOpen = points >= cost`로 열 수 있는지 판단합니다.
- 버튼에는 `disabled={!canOpen}`을 줍니다. 비활성화된 버튼은 클릭되지 않고, CSS로 회색으로 표시됩니다.
- `{!canOpen && (...)}` 조건부 렌더링으로 "⚠️ 포인트가 부족합니다! 박스를 열려면 200P 이상 필요합니다." 문구를 보여 줍니다.
- 포인트가 200P 이상으로 다시 올라가면 `canOpen`이 자동으로 true가 되어 버튼과 경고 문구가 함께 바뀝니다.

### 3.4 당첨 기록 관리

**목록 표시**

- `wins.map()`으로 당첨 기록을 하나씩 꺼내 `<li>`로 그립니다.
- `key`에는 상품 이름이 아니라 `recordId`를 씁니다. 같은 상품이 여러 번 당첨되어도 기록마다 번호가 달라서 각 항목을 구분할 수 있습니다.
- 순서 번호는 `index + 1`로 표시합니다.

**상품별 개수**

- `countPrize(prizeId)`는 `wins.filter(...)`로 같은 상품의 기록만 골라 그 개수를 셉니다.
- 상품 4종 각각에 대해 개수를 계산해 "🍫 초콜릿 2개"처럼 표시합니다.

**더블클릭 삭제**

- 기록 항목에 `onDoubleClick`을 달아 `deleteWin(recordId)`를 호출합니다.
- `deleteWin`은 `filter`로 그 번호의 기록만 뺀 새 배열로 바꿉니다.
- 포인트는 바뀌지 않습니다. 이미 사용한 200P와 받은 당첨 포인트를 그대로 둡니다.
- 목록 번호는 배열 위치로 매기므로, 삭제하면 뒤에 있던 번호가 앞으로 당겨집니다.

**우클릭 상세 정보**

- 기록 항목에 `onContextMenu`를 달아 `showDetail(win.prize)`를 호출합니다.
- `selectedPrize`에 상품을 저장하면 `PrizeList` 아래에 상세 카드가 나타납니다. 카드에는 상품 이름, 설명, 상품 가치(쉼표 표시), 당첨 확률, 당첨 포인트, 현재 보유 개수가 나옵니다.
- "닫기" 버튼을 누르면 `closeDetail`이 `selectedPrize`를 `null`로 바꾸어 카드를 숨깁니다.
- 현재 구현은 `preventDefault()`를 쓰지 않아서, 상세 정보가 열릴 때 브라우저 기본 우클릭 메뉴도 함께 뜹니다.

### 3.5 게임 초기화 (`resetGame`)

'초기화' 버튼은 "획득한 선물" 제목 옆에 있으며, `resetGame`이 다음 값을 모두 처음 상태로 되돌립니다.

- 닉네임 → "럭키학생" (`RESET_NICKNAME`)
- 포인트 → 1,000P (`START_POINTS`)
- 당첨 목록 → 빈 배열
- 마지막 당첨 결과 → `null`
- 박스 이용 횟수 → 0
- 상세 정보 → 닫힘
- 안내 메시지 → 처음 문구

## 4. 추가 기능의 구현과 실행 결과

과제 PDF 5장의 추가 기능 중 7가지를 구현했습니다. 추가 기능 때문에 기본 규칙과 달라진 부분이 두 가지 있습니다.

- **기본 확률**: 기본 규칙은 상품마다 25%이지만, 추가 기능 ②로 상품마다 확률을 다르게 했습니다.
- **열 수 있는 횟수**: 기본 규칙은 최대 5회지만, 추가 기능 ⑤로 당첨 포인트를 지급하므로 실제 횟수는 당첨 결과에 따라 달라집니다.

### 4.1 상품 4종과 당첨 확률 표시 (①)

**구현 내용**: 럭키박스 열기 버튼 아래에 "이 상자에서 나올 수 있는 선물" 목록을 두고, 상품 카드 4개에 이모지, 이름, 확률, 당첨 포인트를 보여 줍니다.

**구현 방법**: `prizes`를 Props로 넘긴 뒤, `LuckyBox`에서 `map()`으로 카드 4개를 그립니다. 각 카드의 `key`는 상품 `id`입니다.

**관련 파일**: `LuckyBox.js`, `App.css`

**실행 결과**: 플레이어가 게임을 시작하면 바로 어떤 상품이 나오는지, 각 상품이 몇 %의 확률인지 확인할 수 있습니다. 상품 목록은 게임이 진행되어도 바뀌지 않습니다.

📸 캡처: 럭키박스 영역의 상품 4종 카드

### 4.2 상품별 당첨 확률 조정 (②)

**구현 내용**: 모든 상품이 같은 25%로 나오지 않도록, 상품마다 `chance` 값을 정했습니다. 초콜릿 40%, 영화관람권 30%, 곰인형 20%, 무선 이어폰 10%입니다.

**구현 방법**: `pickPrize()`가 0~100 사이 난수를 만들고, 확률을 앞에서부터 누적해 난수가 속한 구간의 상품을 고릅니다(3.2절 참고). 상세 정보 카드의 "당첨 확률"도 상품별 값을 보여 줍니다.

**관련 파일**: `prizes.js`, `App.js`, `PrizeList.js`

**실행 결과**: 같은 조건에서 `pickPrize()`를 100,000번 실행해 당첨 비율을 세었습니다. 결과는 초콜릿 39.8%, 곰인형 20.1%, 무선 이어폰 10.0%, 영화관람권 30.1%였습니다. 설정한 확률과 거의 일치합니다.

### 4.3 기본 닉네임 표시 (③)

**구현 내용**: 닉네임 입력창을 비우거나 공백만 입력하면, "○○님의 보유 포인트" 문구에는 기본 닉네임(추유민)을 보여 줍니다. 입력창 자체는 비어 있는 상태로 두어 "이름 입력" 안내 문구가 보이게 합니다.

**구현 방법**: `PointBoard`에서 `nickname.trim()`이 빈 문자열이면 `DEFAULT_NICKNAME`을, 아니면 입력한 닉네임을 `displayName`으로 씁니다.

**관련 파일**: `PointBoard.js`, `prizes.js`

**실행 결과**: 이름을 입력하면 카드의 이름도 바로 바뀝니다. 입력창을 지우면 "추유민님의 보유 포인트"로 돌아가고, 입력창에는 "이름 입력" 안내 문구가 보입니다.

📸 캡처: 닉네임을 비웠을 때 기본 닉네임이 표시된 화면

### 4.4 확률 오름차순 정렬 (④)

**구현 내용**: 럭키박스에서 보여 주는 상품 카드를 당첨 확률이 낮은 순서로 정렬합니다.

**구현 방법**: `[...prizes].sort((a, b) => a.chance - b.chance)`로 배열을 복사해서 정렬합니다. 원본 `PRIZES` 배열의 순서는 바뀌지 않으므로, 당첨 확률 계산 순서에는 영향을 주지 않습니다.

**관련 파일**: `LuckyBox.js`

**실행 결과**: 카드 순서는 무선 이어폰(10%) → 곰인형(20%) → 영화관람권(30%) → 초콜릿(40%)입니다.

📸 캡처: 확률 순서대로 정렬된 상품 카드

### 4.5 당첨 상품별 포인트 지급 (⑤)

**구현 내용**: 당첨된 상품에 따라 포인트를 지급합니다. 초콜릿 50P, 영화관람권 100P, 곰인형 150P, 무선 이어폰 300P입니다.

**구현 방법**: 박스를 열 때 포인트를 `prev - BOX_COST + prize.reward`로 계산합니다. 상품을 열 때마다 한 번에 이 세 값이 함께 반영됩니다. 당첨 메시지, 상품 카드, 상세 정보에도 지급 포인트를 함께 보여 줍니다.

**관련 파일**: `prizes.js`, `App.js`, `LuckyBox.js`, `PrizeList.js`

**실행 결과**: 상품 한 번 열기에 따른 포인트 변화는 다음과 같습니다.

| 당첨 상품   | 차감  | 지급  | 순변화 |
| ----------- | ----- | ----- | ------ |
| 초콜릿      | -200P | +50P  | -150P  |
| 곰인형      | -200P | +150P | -50P   |
| 무선 이어폰 | -200P | +300P | +100P  |
| 영화관람권  | -200P | +100P | -100P  |

한 번 열 때의 평균 지급액은 0.4×50 + 0.2×150 + 0.1×300 + 0.3×100 = 110P입니다. 박스 비용 200P보다 적으므로, 평균적으로는 포인트가 줄어들어 결국 게임이 끝납니다. 기록을 삭제해도 지급된 포인트는 그대로 남습니다.

📸 캡처: 당첨 메시지와 포인트가 함께 바뀐 화면

### 4.6 보유 포인트와 이용 횟수 카드 (⑥)

**구현 내용**: 보유 포인트와 박스 이용 횟수를 두 개의 카드로 나누어, 큰 숫자로 보여 줍니다. 보유 포인트 카드는 더 넓게 만들어 가장 중요한 정보임을 드러냈습니다.

**구현 방법**: `PointBoard`에서 `.stat-cards` 안에 `.point-card`(flex 2)와 `.count-card`(flex 1)를 나란히 배치합니다. 숫자는 30px 굵은 글씨로, 카드마다 다른 색 테두리를 줍니다.

**관련 파일**: `PointBoard.js`, `App.css`

**실행 결과**: 포인트가 바뀔 때마다 큰 숫자가 함께 바뀌고, 박스를 열 때마다 이용 횟수가 1씩 올라갑니다.

📸 캡처: 보유 포인트와 이용 횟수 카드

### 4.7 브라우저 탭 제목 고정 (⑦)

**구현 내용**: 브라우저 탭 제목을 "랜덤 럭키박스 게임"으로 고정합니다.

**구현 방법**: 탭 제목은 `index.html`의 `<title>`에 정해져 있어 게임 상태와 관계없이 고정됩니다.

**관련 파일**: `App.js`, `public/index.html`

**실행 결과**: 포인트가 바뀌어도 탭 제목은 그대로 "랜덤 럭키박스 게임"입니다.

📸 캡처: 브라우저 탭 제목이 보이는 화면 (선택)

## 6. 사용한 React 기능 정리

| React 기능                  | 사용 위치                                               | 용도                                                              |
| --------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------- |
| 함수형 컴포넌트             | 모든 파일                                               | 화면 조각을 함수로 나눔                                           |
| `useState`                  | `App.js`                                                | 닉네임, 포인트, 당첨 기록 등 값이 바뀌면 화면을 다시 그리는 State |
| `useRef`                    | `App.js`                                                | 기록 번호 카운터. 바뀌어도 화면을 다시 그리지 않음                |
| Props                       | 모든 자식 컴포넌트                                      | 부모(App)가 값과 함수를 자식에게 전달                             |
| 분할 대입 Props             | 모든 자식 컴포넌트                                      | 매개변수에서 필요한 Props만 꺼내 씀                               |
| 이벤트 처리                 | `onChange`, `onClick`, `onDoubleClick`, `onContextMenu` | 입력, 박스 열기, 삭제, 상세 보기 처리                             |
| `map()` + `key`             | `LuckyBox.js`, `PrizeList.js`                           | 상품 카드와 당첨 기록 목록을 반복해서 그림                        |
| 조건부 렌더링               | `LuckyBox.js`, `PrizeList.js`                           | 당첨 전후 화면, 기록 유무, 상세 카드, 경고 문구 표시              |
| Fragment `<>...</>`         | `LuckyBox.js`, `PrizeList.js`                           | 불필요한 태그 없이 여러 요소를 묶음                               |
| `disabled` 속성             | `LuckyBox.js`                                           | 포인트가 부족하면 버튼을 누를 수 없게 함                          |
| 상수 파일 분리              | `prizes.js`                                             | 설정값과 상품 데이터를 한곳에서 관리                              |
| `import` / `export default` | 모든 파일                                               | 컴포넌트와 상수를 파일 사이에서 가져다 씀                         |

위 표 외에 `filter`, `sort`, 전개 연산자(`...`) 같은 JavaScript 기본 문법을 함께 사용했습니다.
