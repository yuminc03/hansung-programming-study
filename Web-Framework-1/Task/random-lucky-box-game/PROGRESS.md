- 요구사항 PDF를 다시 검토했다(예시 화면 이미지 포함). 닉네임 처리가 PDF 규칙과 달라서 고쳤다.
  - 기본 닉네임: 빈 값 → 본인 성명 '추유민' (`DEFAULT_NICKNAME`)
  - 초기화 닉네임: 빈 값 → '럭키학생' (`RESET_NICKNAME`)
  - 두 값은 `prizes.js`에 상수로 두고, 테스트도 같은 상수로 검증한다.
- 테스트 7개 통과, `CI=true npm run build` 성공.
- 남은 선택 사항: 예시 화면처럼 "닉네임님의 보유 포인트" 문구 표시, 초기화 버튼과 안내 문구 위치 조정.
- 화면 디자인을 PDF 4장 실행 화면 예시에 맞췄다. 예시 이미지의 픽셀 색상을 직접 추출해서 같은 색을 썼다.
  - 레이아웃: 연보라 배경(`#f7f3ff`) 위에 흰 카드(폭 760px) 하나를 두고, 제목(`#6851a1`)과 부제 "상자를 열고 특별한 선물을 획득하세요!"를 넣었다.
  - PointBoard: 연보라 박스, "닉네임" 입력창, "**추유민**님의 보유 포인트: **1,000P**" 문구. 박스 이용 횟수는 같은 줄 오른쪽에 둔다(요구사항상 표시가 필요해서 예시에 추가했다).
  - LuckyBox: 연분홍 박스, 큰 🎁, "어떤 선물이 나올까요?", "럭키박스를 열어 행운을 확인하세요!", 분홍 버튼. 당첨 후에는 🎁 자리에 당첨 상품이 나온다.
  - PrizeList: "획득한 선물 (N개)" 제목 옆에 하늘색 초기화 버튼을 두었다(초기화 버튼을 App에서 이 위치로 옮기고 `onReset` prop으로 전달). 빈 목록 문구는 "아직 획득한 선물이 없습니다."다. 당첨이 있으면 상품별 개수 태그와 번호 목록이 나온다.
  - 조작 안내 문구를 카드 맨 아래에 항상 표시한다.
- Edge headless로 초기 화면, 3회 오픈 후 우클릭 상세, 5회 오픈 후 포인트 부족 화면을 캡처해서 예시 이미지와 비교했다. 테스트 7개 통과, 빌드 성공.
- 수업 자료(`../react-수업내용/` 1~7주차 PDF, 슬라이드 이미지 포함)와 비교해서 코드를 정리했다. 기준: React 문법만 수업에서 배운 것으로 제한하고, HTML/CSS/JS는 안다고 본다.
  - `index.js`: `React.StrictMode`와 `reportWebVitals`를 빼고 6주차 교재처럼 `root.render(<App />)`로 바꿨다. 쓰이지 않게 된 `reportWebVitals.js`를 삭제했다.
  - `PointBoard.js`: JSX 띄어쓰기용 `{" "}`를 없애고 문장을 한 줄 흐름으로 정리했다.
  - `PrizeList.js`: 오른쪽 클릭 시 `e.preventDefault()`를 쓰지 않기로 했다(사용자 결정). 그래서 상세 정보와 함께 브라우저 기본 메뉴도 뜬다.
  - JavaScript 정리: 당첨 기록에 상품 객체를 그대로 저장해 `find()`를 없앴다. 상품별 개수는 `reduce` 대신 `filter().length`로 센다.
  - 수업 범위 밖인 jest/Testing Library 자동 테스트(`App.test.js`, `setupTests.js`)를 삭제했다. 삭제 전 마지막으로 7개 테스트가 모두 통과하는 것을 확인했다.
- 삭제 후에는 Edge headless로 시작 → 3회 오픈 → 우클릭 상세 → 더블클릭 삭제 → 포인트 소진 → 초기화를 차례로 실행해서 상태가 모두 맞는지 확인했다. `CI=true npm run build` 성공.
- 추가 기능(PDF 5장) 3가지를 구현했다.
  - 당첨 확률 조정: `prizes.js`에 `chance`를 추가하고(초콜릿 40, 영화관람권 30, 곰인형 20, 무선 이어폰 10), `App.js`의 `pickPrize()`가 누적 확률로 상품을 고르게 했다. 실제 `pickPrize` 코드로 10만 번 시뮬레이션해서 39.8% / 20.1% / 10.0% / 30.1%가 나오는 것을 확인했다. 상세 정보의 확률도 상품별 값으로 바꿨다.
  - 상품 4종 표시: `LuckyBox.js`에서 열기 버튼 아래에 "이 상자에서 나올 수 있는 선물" 카드 4개(이모지, 이름, 확률)를 `map`으로 그린다.
  - 기본 닉네임 표시: `PointBoard.js`에서 닉네임이 비었거나 공백만 있으면 "추유민님의 보유 포인트"로 보여준다. 입력창은 비어 있는 그대로 placeholder가 보인다.
  - Edge headless로 입력 비움, 공백만 입력, 이름 입력, 다시 비움, 상세 확률 표시를 확인했다. `CI=true npm run build` 성공.
- UI 개선과 기능 추가 5가지를 구현했다.
  - 당첨 포인트 지급: `prizes.js`에 `reward`(초콜릿 50, 영화관람권 100, 곰인형 150, 무선 이어폰 300)를 추가했다. 박스를 열면 `prev - BOX_COST + prize.reward`로 계산한다. 평균 지급액은 110P로 비용 200P보다 적어서 게임이 언젠가 끝난다. 메시지에 "(+50P 적립)"처럼 표시하고, 상품 카드와 상세 정보에도 보여준다.
  - 상품 목록 정렬: `LuckyBox.js`에서 복사한 배열을 확률 오름차순(10% → 40%)으로 정렬해서 그린다.
  - 포인트·이용 횟수 UI: `PointBoard.js`를 두 개의 카드(보유 포인트 30px 숫자, 박스 이용 횟수 30px 숫자)로 바꿨다.
  - 탭 제목: 포인트로 탭 제목을 바꾸던 `useEffect`를 제거해서 "랜덤 럭키박스 게임"으로 고정했다.
  - Edge headless로 버튼이 비활성화될 때까지(10회) 열면서, 매번 "이전 포인트 − 200 + 상품 포인트"와 화면 값이 맞는지, 정렬 순서와 탭 제목을 확인했다. `CI=true npm run build` 성공.
- 과제 PDF 기본 조건 최종 점검: 개발 서버(`npm start`)를 Edge headless로 띄웠다. `Math.random`을 고정해서 ①~⑤ 규칙 27개 항목을 시나리오로 확인했고 모두 통과했다. 콘솔 오류와 경고는 없었다(React DevTools 안내 info만 있음).
  - 확인한 항목: 시작 닉네임/포인트/빈 목록, 200P 사용, 결과 표시, 목록 추가, 같은 상품 반복 당첨, 순서 목록과 개수, 우클릭 상세, 더블클릭 삭제(포인트 미반환), 200P 미만 비활성화와 안내, 초기화(닉네임 '럭키학생', 1,000P, 목록·결과·횟수 비움).
  - PDF 기본 규칙과 다른 점 2가지는 모두 추가 기능 때문이다: 기본 확률 25% → 상품별 확률, 최대 5회 → 당첨 포인트 지급으로 횟수가 달라짐.
- 보고서 작성을 위해 JS 파일 6개(App, PointBoard, LuckyBox, PrizeList, prizes, index)에 한국어 주석을 달았다: 파일 역할, 함수 설명, 변수/State/Props 설명, 코드 줄별 의미. JSX 안에서는 `{/* */}`를 요소 위 별도 줄에 달았다.
  - Babel로 주석과 위치 정보를 뺀 AST를 커밋 전 코드와 비교해서 6개 파일 모두 코드가 그대로인 것을 확인했다. 빌드 성공, 기본 조건 27개 항목 재검증 통과, 콘솔 오류 없음.
